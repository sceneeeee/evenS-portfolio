<section id="overview" className="case-section">
<span className="eyebrow">01 / OVERVIEW</span>

## Preserve the navigation prior. Change the sensor interface.

ETPNav uses learned waypoints from panoramic RGB-D observations to build a topological representation and follow language instructions. This project studies what happens when dense depth is replaced by sparse, MID360-like geometry.

The experimental boundary is deliberately narrow: adapt the waypoint interface while keeping GraphMap and the downstream planner frozen wherever possible. This makes sensor sparsity, proposal semantics, and graph interaction easier to investigate separately.

<div className="callout"><strong>Current scope</strong><p>Controlled Habitat experiments are concluded. Stage 5 learned adaptation was not completed; no native Isaac LiDAR or physical MID360 deployment occurred.</p></div>
</section>

<section id="problem" className="case-section">
<span className="eyebrow">02 / PROBLEM & MOTIVATION</span>

## Geometric feasibility is only part of the interface.

Replacing a learned RGB-D front-end with geometry-based waypoints changes more than input density. Candidate distance, angular coverage, learned feature statistics, and graph association can all alter the decisions available to the planner.

The engineering question is whether the original navigation prior can remain useful under sparse observations without redesigning the whole stack. Controlled ablations test one hypothesis at a time rather than changing perception, planning, and execution together.

<section id="implementation" className="case-section">
<span className="eyebrow">05 / TECHNICAL IMPLEMENTATION</span>

## Design around the downstream contract.

### Sparse input construction

Dense depth is reconstructed into metric geometry, sparsified with a deterministic MID360-like angular abstraction, and projected using nearest returns. This is a controlled engineering abstraction; it does not reproduce the full Livox sampling process, motion distortion, or sensor noise.

### Bounded proposal suppression

The proposal map has circular angle and bounded distance dimensions. A geometry-specific non-maximum suppression correction respects that distinction. The original ETPNav NMS implementation remains unchanged.

### Candidate association

GraphMap can merge proposals with ghost nodes or absorb them into visited nodes. Local candidate diversity is therefore evaluated together with the graph actions that remain after association.

### Mechanism checks before navigation claims

Activation tracing and fixed feature-statistics alignment are static mechanism studies. Their conclusions are kept separate from navigation evaluation. Stage 5 remained an unfinished prototype: there was no completed formal training, held-out generalization acceptance, or demonstrated navigation recovery.
</section>

### What changed the next engineering decision

- **Bounded NMS improved the geometry variant**, but remained below the original baseline on this panel.
- **MRU corrected the distance tendency without recovering navigation.** Matching the average proposal distance was insufficient.
- **G-Min improved several path-quality measures**, while its success rate did not exceed bounded NMS.
- **Sparse depth zero-shot collapsed.** This motivated tracing where the frozen predictor stopped responding usefully.

<section id="failure-analysis" className="case-section">
<span className="eyebrow">07 / FAILURE ANALYSIS</span>

## Follow the failure past the first representation.

### Raw waypoints do not equal graph actions

One audited configuration contained 595 raw candidates: 411 became new ghost nodes, 25 merged with existing ghosts, and 159 were absorbed into visited nodes. Very short-range candidates were particularly vulnerable to absorption. This is a configuration-specific audit, not a general distribution claim.

<EvidenceMedia asset={etpnavAssets.graph} />

### Predictor collapse occurs downstream

Sparse inputs retained partial structure after the frozen depth encoder. Activation tracing located complete collapse later in the frozen waypoint predictor, leaving effectively bias-driven waypoint logits. The evidence points toward an interface/domain-shift problem rather than simply an empty encoder representation.

<EvidenceMedia asset={etpnavAssets.activation} />

### Simple statistics did not repair the interface

Channel-wise mean/std alignment failed to restore classifier activity or waypoint diversity on held-out static observations. This negative mechanism result motivated an unfinished learned-adapter prototype, not a successful adaptation result.
</section>

<section id="limitations" className="case-section">
<span className="eyebrow">08 / LIMITATIONS & NEXT STEPS</span>

## Keep the validation boundary explicit.

- The 20 development episodes are a small, repeatedly used comparison panel.
- The sparse observation model approximates selected sensor properties, not a complete native MID360 simulation.
- Static activation recovery, if achieved, would still require controlled navigation validation.
- Stage 5 learned adapter was not completed; no formal held-out generalization or waypoint recovery was demonstrated.
- Isaac Sim native LiDAR, localization, and real MID360 robot execution were not implemented in this concluded project.

The earlier Isaac Sim / MID360 hardware transfer plan was discontinued; the project closed with controlled experiments and documented negative findings.
</section>
