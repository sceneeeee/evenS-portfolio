<span className="eyebrow">01 / OVERVIEW</span>

## Integrating model, protocol and simulator — not claiming navigation success.

The completed engineering deliverable connects a model-side policy service and a separately owned Habitat evaluator. The showcased real Habitat execution uses a **Deterministic Fake Policy** to validate the HTTP/queue/environment interfaces; no NaVIDA checkpoint is loaded in this video.

<section id="problem" className="case-section">
<span className="eyebrow">02 / PROBLEM & MOTIVATION</span>

## Make model output executable, bounded and auditable.

A vision-language policy emits action text, whereas Habitat advances using atomic simulator actions. Connecting these systems requires episode identity, RGB observations, step sequencing, strict parsing and traceable decisions—not simply a direct model call. The stateful interface separates a *policy decision* from the queued environment steps that realize that decision.
</section>

<section id="architecture" className="case-section case-section-wide">
<span className="eyebrow">04 / SYSTEM ARCHITECTURE</span>

## HTTP decisions versus atomic simulator actions.

The model-side process maintains a stateful episode and action queue. The evaluator sends current RGB, instruction and step identity, then consumes one bounded action per `env.step()`. In the fixed-action showcase a deterministic policy substitutes for inference; the transport and Habitat stepper remain real.

<section id="implementation" className="case-section">
<span className="eyebrow">05 / TECHNICAL IMPLEMENTATION</span>

## Measured physical-action semantics in simulation.

- Habitat 0.3.3 scene loading/reset and RGB rendering completed in `skokloster-castle`.
- Forward action displacement was approximately **0.249999864 m**; single turns approximately **±15°** and consecutive left turns approximately **30°**; explicit STOP terminated the episode.
- A normal Stage C case produced **4 HTTP requests / 4 real environment steps**.
- An invalid-output case produced **3 requests / only 2 real steps**; invalid model output ended the run without a hidden replacement action.

The original 4-bit checkpoint was also executed historically on an RTX 4060 Ti 8 GiB, but that separate run is **not** the policy shown in the engineering video.
</section>

<section id="results" className="case-section case-section-wide">
<span className="eyebrow">06 / EXPERIMENTS & RESULTS</span>

## The integration works; navigation success is not established.

| Validation | Recorded evidence | Interpretation |
|---|---|---|
| Deterministic real-Habitat showcase | **21 actions**, **21 HTTP requests**, **11 fixed decisions** | Verified interface and fixed-action execution, not learned policy inference |
| Collision/termination | **0 collisions**, explicit **STOP** | Specific scripted episode only; not safety or search success |
| Video export | 640 × 480, 21 frames at 2 fps, 10.5 s | Playback rate is not measured control throughput |
| Local tests | Model-side **98 passed / 1 skipped**; evaluator **56 passed** | Software checks; CI does not run the full simulator |
| Historical real NaVIDA grounded episode | **80 steps**, success **0**, SPL **0**, final goal distance ~**8.620 m** | Model failed the task; a separate Oracle control succeeded |

The early five-step real-checkpoint HTTP smoke was not aligned with the random PointNav goal. The later grounded 80-step run was instruction-linked and **failed**. These are historical experiments, not newly rerun evidence or official R2R/RxR results.
</section>

<section id="failure-analysis" className="case-section">
<span className="eyebrow">07 / FAILURE ANALYSIS</span>

## Separate protocol correctness from policy performance.

The evaluator intentionally did **not** substitute `move_forward` or another fallback after invalid model text. An invalid-output path issued fewer real environment steps than HTTP requests. Likewise, a functioning inference service and a successful Oracle reference do not mean the NaVIDA policy navigated successfully; its historical grounded run stopped at the wrong location.
</section>

<section id="limitations" className="case-section">
<span className="eyebrow">08 / LIMITATIONS</span>

## An engineering integration, not a navigation benchmark.

There is no reported standard VLN benchmark, multi-scene generalization study, real-robot deployment or production-hardened service. The deterministic-policy video uses fixed actions and does not follow the task goal. The Habitat scene and licensed assets are not redistributed as raw datasets.
</section>
